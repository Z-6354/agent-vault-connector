## Product paths and reproducible entrypoints

Run `npm ci --no-audit --no-fund` and `npm run build` with Node 22.13+ within Node 22. Browser execution requires system Chromium; acceptance additionally requires Python 3 for the controlling PTY. No model, ASR backend or model credential is required.

Normal startup:

```sh
node dist/src/cli.js init --data-dir /absolute/private/vault
node dist/src/cli.js serve --data-dir /absolute/private/vault --port 43120
```

Initialization requires a real interactive terminal and hidden passphrase input. No secret command argument or environment parameter exists. Server listens only on exact `http://127.0.0.1:<port>` and starts locked. Sign in, then separately unlock. S0/S1/S2, sole authenticated administrator, strict cookies, Host/Origin/CSRF checks, 15-minute management idle expiry and epoch invalidation remain the shared policy. Execution does not prolong that session.

Browser execution is explicitly configured through a private current-user-owned `0600` file:

```json
{"mode":"production","browser":{"enabled":true,"executablePath":"/usr/bin/chromium","headless":true}}
```

Pass `--product-config /absolute/private/product.json` to `serve`. The only registered browser site is the synthetic login at `http://127.0.0.1:43122`, with fixed login/form/account paths and selectors. An unconfigured host reports unsupported. Management **Refresh approvals** shows authenticated execution principal, site/origin, session, connection/version, action and expiry. Only the authenticated management UI can approve; the MCP surface can request and inspect approval but cannot approve. Fill and login submit are independently approved, single-use actions. The trusted host retains context/document identity and enforces original TTL, epoch and record/status/rules policy; no caller URL/selector/script or secret DOM/cookie output is accepted. Submit uses a signed core ticket and durable journal; reconstructible canonical input permits saved replay after ephemeral approvals disappear without another POST. Fixed account status can verify retained-cookie reuse without reviving old document permissions.

OAuth setup is available in the default management UI. Without a client, the provider is disabled with `client_not_configured`. Manually register a provider application with its exact displayed callback and enter client ID/secret using the protected UI. Configuration is encrypted under version-specific authenticated context in schema4, with expected-version CAS; password inputs clear immediately and the secret is never read back. Issued material also binds the client generation and exact provider/mode/endpoints. Client replacement moves active grants to `needs_user_action` without deleting unresolved leases; fresh authorization cannot carry forward a refresh token from the previous client. Production GitHub/Google authorize/token/identity/revoke endpoints are immutable. Local redirect callbacks use `/management/oauth/callback/github` or `/google` at the exact server IP/port. The callback's static GET relay strips code/state from browser history and consumes them only through authenticated same-origin CSRF POST, preserving SameSite=Strict cookies.

Review/save creates a pending OAuth connection with fixed minimum GitHub `read:user` or Google `openid email` scopes. **Authorize** returns an expiring human-click link; state/PKCE binds management session, owner, target connection/versions, client version, callback, epoch and expiry. Actual `execute_operation` consumes encrypted token material for `github.current_user` or `google.userinfo`, refreshing expired material before dispatch under durable lease/CAS. Concurrent same-connection requests coalesce to one refresh. Missing offline material requires authorization again. A lost rotating refresh response retains an unresolved lease and `needs_user_action`, including restart; it cannot retry the old refresh token. Management material reconciliation abandons the old material with reviewed evidence and requires fresh authorization. **Revoke OAuth** handles provider-side revocation; generic local revoke/deletion alone does not revoke the upstream grant.

The stdio bridge offers six core execution/status tools plus seven browser tools. It reads only an explicitly supplied protected execution credential file, maps it to stable `execution:local`, and cannot manage, approve or unlock. Internal authenticated HTTP routes are not a remote Streamable HTTP MCP server or MCP OAuth authorization server.

The isolated acceptance command is:

```sh
node scripts/v1-product-acceptance.mjs
```

It creates short private scratch directories, actual CLI PTY initialization with `--synthetic true`, a private startup config and isolated HOME/TMPDIR/XDG directories. Synthetic mode requires the private initialization marker; a marked vault cannot start in production/default mode. Separate GitHub and Google literal-loopback HTTP simulators implement their respective authorization/PKCE/token/identity/refresh/revocation behavior. Production config rejects endpoint overrides. The browser fixture uses fixed port43122, which must be free. Script cleanup stops product/bridge/browser/fixtures and removes scratch data. Success produces only sanitized JSON and a management screenshot; no callback URLs, secret parameters or raw provider/Playwright diagnostics are retained.
