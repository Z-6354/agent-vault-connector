# 前置凭据安全连接器规范 (Credential Pre-Ingress Guard Spec)

> 适用对象：任何 LLM Agent 的开发者与用户。本规范定义凭据进入 Agent 系统前的强制拦截铁律，配套技能见 `source/skills/credential-pre-ingress-guard/SKILL.md`。

## 为什么需要它

LLM Agent 的对话历史会物理落地并上传到模型服务端。**密码/Token 一旦被贴入对话框，泄露就已经发生且不可撤销**——删除消息、撤回提示都只是界面动作，服务端记录仍在。因此凭据安全的第一道防线必须在用户"敲下回车键之前"，而不是事后处理。

这不是某个 Agent 的特殊问题，而是所有以聊天为交互面的 Agent 系统的共性风险：任何时刻（安装引导、使用询问、任务执行）用户都可能被引导或自发地把明文凭据送进上下文。

## 核心铁律

**一发出去就算泄露。** Agent 侧的职责是拦截输入，不是处理已输入。

## 三个强制拦截点

### 1. 安装完成时刻

新连接器/新客户端安装完成、用户询问使用指引的第一时间，必须前置告警：

> 「本工具不会也不会要求您在聊天框输入密码。请打开安全桌面伴侣 / 唤起掩码输入卡片完成凭据录入。」

安装引导的任何步骤中不得出现"把 Token 发给我/贴进来"类话术及其变体（"发个截图也行"、"直接粘贴即可"）。

### 2. 使用询问时刻

用户问"怎么用/要填密码吗"时，回答的第一句必须是安全通道引导，然后才是使用说明。Agent 感知到任务需要凭据时，只能：

- 引导用户打开安全桌面端；
- 或唤起掩码输入卡片（原生弹窗走 IPC 直入存储，不经聊天流）。

即使用户主动贴入明文，Agent 也不读、不复述、不存档（复述确认本身就会二次落上下文），并立即提醒撤回与轮换。

### 3. 任务执行时刻

Agent 执行任务需要凭据时，先检索已入库凭据（一次存入、全网共享），命中即用；缺失才引导用户走安全通道补录。严禁向用户二次索要明文。

## 实现要求（Agent 开发者）

1. **掩码通道优先于一切文本交互**：为系统提供至少一条不经过聊天流的凭据录入路径（原生弹窗/独立无回显进程）。
2. **拦截点内建**：三个时刻（安装完成、使用询问、任务执行）的响应模板中硬编码安全引导，不依赖模型自觉。
3. **凭据消费与录入分离**：Agent 运行时通过受控 API/MCP 取用凭据，明文不回流模型上下文。
4. **误贴应急**：检测到用户消息含疑似明文凭据（高熵字符串、已知前缀如 `ghp_`、`sk-`）时，立即提醒轮换。

## 用户侧须知

- 任何时候都不要把密码/Token/私钥贴进对话框，包括"只发一次"、"截图形式"。
- 录入凭据只走掩码弹窗或安全桌面端。
- 若已误贴：立即在对应平台轮换该凭据（作废重发），聊天记录无法可靠清除。

## 与本仓库（agent-vault）的关系

agent-vault 的设计正体现了本规范：凭据经掩码通道录入、加密落盘、通过 MCP/API 供 Agent 受控消费——明文永不经过聊天流。本规范将该设计原则提炼为任何 Agent 系统都可采用的通用铁律。
