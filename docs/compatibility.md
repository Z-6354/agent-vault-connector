The local V1 exposes a standard **stdio MCP execution bridge**. Its authenticated internal HTTP routes are not a remote Streamable HTTP MCP endpoint or an MCP OAuth authorization server. Remote-only/OAuth-only clients remain unsupported pending actual implementation and authorized deployment tests. No public port, remote endpoint or external account was used for this delivery.

`external_reference` is metadata only and always reports `can_execute=false`; native platform login does not transfer authority. `src/delegation.ts` provides a separate trusted delegation interface tested against an actual **synthetic loopback host**, including center/upstream identities, local/upstream scope intersection, resources/audience/endpoints, expiry, revocation and reachability. It is not any of these agents' formal API and is not wired as a production MCP executor. Existing native reuse and center delegated execution therefore remain separate, unverified cells for all five agents.

A future agent acceptance run must record the actual product/version, isolated entry/profile, connection direction, deployment machine, protocol/auth, exact synthetic reproduction steps, successful fixed operation, lock/revoke refusal with no mock hit, unknown-operation refusal, recovery, and secret-free logs/output. None is inferred from documentation, schema discovery or this project's SDK tests.
